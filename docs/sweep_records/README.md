# Sweep records — the filing cabinet

One folder, a series of short documents: every sweep run's reports, filed by date (her design). The guide keeps
nothing month-specific; it points here. Search this folder for "when did X start", "how long has Y blocked us".

## The files — three per run, each written once

| File | Written by, when | What it holds |
|---|---|---|
| `<date>_<pile>_1_report.md` | The QC (`.claude/skills/sweep-qc/SKILL.md`). The monthly routine saves it overnight in the run folder as `report.md` and files it here once she is in the session; a session for her home run files it at once | The run's report exactly as she was given it |
| `<date>_<pile>_2_plan.md` | The session, once she and it have been through every fault | Four headings: **Put aside until next run** · **Tentative conclusions** · **Fixes to make** · **Process changes** — short bullets |
| `<date>_<pile>_3_close.md` | The session, at its end | What was fixed and tested, what changed in the instructions, what is still open — short bullets |

`<date>` is the run's date (`2026-11-19`), `<pile>` is `container` or `home`. A part is never rewritten after it
is filed; a later correction goes in the next run's files. No narrative, no transcript — the same short style
she was given.

## How the next run uses it

The next run's QC reads the latest `_2_plan.md` and `_3_close.md` of the same pile and reports on each carried
item: is a "put aside" site back; is a tentative conclusion firming up (a second month blocked); did each fix
hold in the case it was written for.
